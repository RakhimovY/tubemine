## 0. Context

TubeMine is a hosted SaaS that analyzes any YouTube video's comments and returns sentiment, top words, and emoji frequency. Phase 0 launched 2026-05-15 at https://tubemine.vercel.app. Current state: 1 paying customer at $19/mo, 88 visitors / 138 pageviews in last 7 days, 63% of traffic from Threads RU.

Existing schema (`supabase/migrations/00_init.sql`):

- `profiles` (user_id, tier, welcome_sent_at, created_at, updated_at)
- `usage` (user_id, month, comments_used, updated_at) — monthly quota counter
- `subscriptions` (user_id, polar_subscription_id, polar_customer_id, status, current_period_end, cancel_at_period_end)
- `webhook_events` (event_id, event_type) — idempotency for Polar webhooks

**No persistence for analyses.** Each `POST /api/extract` is stateless: fetch comments via YouTube Data API → score sentiment → return aggregates → forget. The UI design generated by Claude Design (Dashboard "Recent analyses", landing copy "Sign in and TubeMine remembers your history", /history page) promises features the backend does not deliver. This SPEC closes that gap.

**Sentiment reality** (`src/lib/sentiment/index.ts`): lexicon-based scorer, EN + RU treated equally, not ML. Returns `aggregate.languages` and `aggregate.ruShare`. No "experimental beta" flag for Russian — RU is first-class.

**Traffic reality** (per `~/vault/me/social-accounts.md`): 63% of TubeMine visitors arrive from Threads (RU). App is currently EN-only. Founder is bilingual and posts in both EN (X, LinkedIn, dev.to, Reddit) and RU (Threads, IG, Telegram). i18n matches the actual user distribution, not a hypothetical future market.

## 1. Goals

1. Every UI promise reflects real backend behavior. No fabricated features by the time Track C integrates.
2. TubeMine UI is bilingual (EN + RU) with infrastructure that supports adding locales later without rewrites.
3. Saved analyses persist for 30 days with hard-delete semantics (GDPR right-to-erasure friendly).
4. New endpoints follow the existing service-role-write + RLS-read pattern.
5. No regression in extract, CSV gate, OAuth, checkout, Polar webhooks, or Vercel Analytics events.

## 2. Non-goals

- Trial functionality (with or without card-on-file). Out per user decision 2026-05-18.
- Public REST API for third-party integration.
- ML-based sentiment (we stay lexicon).
- Bulk video analysis (one URL at a time).
- Raw comment storage (only aggregates).
- Privacy + Terms RU translation (lawyer review required; ships EN-only with RU-locale disclaimer until reviewed).
- UI translation beyond EN + RU (Spanish, Portuguese, German are sentiment lexicon roadmap, not UI roadmap).
- Pro-tier retention extension beyond 30 days (avoids churn risk from data loss after cancel).
- Soft-delete with retention shadow (hard-delete only).
- Background queue / job runner (best-effort inline writes are sufficient at current traffic).

## 3. Track B1 — Backend persistence

### 3.1 Database

New table `public.analyses`:

```sql
create table public.analyses (
  id              uuid primary key default gen_random_uuid(),
  user_id         uuid not null references auth.users on delete cascade,
  video_id        text not null,
  video_title     text,
  channel_name    text,
  thumbnail_url   text,
  comment_count   int  not null,
  sentiment       jsonb,
  top_words       jsonb,
  emoji_frequency jsonb,
  processed_at    timestamptz not null default now(),
  expires_at      timestamptz not null default (now() + interval '30 days'),
  unique (user_id, video_id)
);

create index analyses_user_id_processed_at
  on public.analyses (user_id, processed_at desc);
create index analyses_expires_at
  on public.analyses (expires_at);

alter table public.analyses enable row level security;

create policy "users read own analyses"
  on public.analyses for select
  using (auth.uid() = user_id);

create policy "users delete own analyses"
  on public.analyses for delete
  using (auth.uid() = user_id);
```

**JSONB shapes:**

- `sentiment` — `SentimentAggregate` from `src/lib/sentiment/index.ts` verbatim (`{ positive, neutral, negative, score, sampleSize, coverage, languages, ruShare }`). Null when sample was too small to aggregate.
- `top_words` — `[{ token: string, count: number }]`, top 50 entries max.
- `emoji_frequency` — `[{ emoji: string, count: number, percent: number }]`, top 20 entries max.

**Unique constraint `(user_id, video_id)`** triggers UPSERT semantics in §3.2: same user re-analyzing the same video updates the existing row (refreshes results + extends `expires_at`).

**Why no raw comment text:** privacy-first selling point. CSV export captures user-side data. Storage cost stays minimal.

### 3.2 Modified endpoint: `POST /api/extract`

Add a non-blocking write at the end of the existing flow:

1. Extract completes successfully, response payload ready.
2. If `userId !== null` (signed-in), call `saveAnalysis(userId, videoId, payload)` wrapped in `try/catch`.
3. `saveAnalysis` performs UPSERT on `(user_id, video_id)` with fresh `processed_at = now()` and `expires_at = now() + interval '30 days'`.
4. Errors logged via `console.warn("[analyses] save failed", { error, userId, videoId })`. Response is returned regardless.

**Why best-effort:** extract is the user's primary value path. A flaky `analyses` insert must never break it.

**Anonymous users:** no row inserted. Privacy preserved for not-signed-in flow.

### 3.3 New endpoints

#### `GET /api/analyses?cursor=<base64>&limit=20`

- Auth required (Supabase server client). Returns 401 if anonymous.
- Returns user's analyses ordered by `processed_at desc, id desc`.
- Cursor: base64-encoded `{ processed_at: ISO, id: uuid }`. Filters to rows older than cursor.
- Default `limit=20`, max `limit=50`.
- Response: `{ items: AnalysisRow[], nextCursor: string | null }`.
- `AnalysisRow` shape: `{ id, video_id, video_title, channel_name, thumbnail_url, comment_count, sentiment, top_words, emoji_frequency, processed_at, expires_at }`.

#### `GET /api/analyses/:id`

- Auth required.
- Returns single analysis. 404 if not found or not owner (RLS handles owner check; UUID format validated via regex).
- Same shape as one `AnalysisRow`.

#### `DELETE /api/analyses/:id`

- Auth required.
- Hard delete (per non-goal §2).
- Returns `{ deleted: true }` on success, 404 if row not found, 401 if not owner.
- RLS policy `users delete own analyses` enforces ownership at DB layer.

### 3.4 Daily retention cron

Vercel Cron Jobs (configured in new `vercel.json`):

```json
{
  "crons": [
    {
      "path": "/api/internal/cron/purge-analyses",
      "schedule": "0 3 * * *"
    }
  ]
}
```

Endpoint `POST /api/internal/cron/purge-analyses`:

1. Validates `Authorization: Bearer ${CRON_SECRET}` (Vercel sends this for cron-triggered requests).
2. Executes `DELETE FROM public.analyses WHERE expires_at < now() RETURNING id`.
3. Returns `{ purged: number }` for observability.
4. Logs purge count.

`CRON_SECRET` env var added to Vercel (production + preview + dev), stored as plain (not sensitive — Vercel sensitive type is write-only per [[references/vercel-sensitive-env-vars]]).

### 3.5 `/history` page

Route `app/[locale]/history/page.tsx` (i18n routing per Track B2):

- **Auth gate:** redirect to `/[locale]/login?next=/[locale]/history` if anonymous.
- **Header:** search input (debounced client-side filter on `video_title` + `channel_name`).
- **Filters:** date range (7d / 30d / all), sentiment dominant (positive / neutral / negative / any). Client-side filters initially; server-side moves to PLAN if perf demands.
- **Grid:** responsive card grid. Card shows thumbnail, video title (clamped 2 lines), channel name, comment count, sentiment dominant chip (color-coded), relative `processed_at` ("3 hours ago"), action menu (Re-analyze, View, Delete).
- **Re-analyze action:** navigate to `/[locale]/?video=<videoId>` — landing handles the auto-analyze path.
- **View action:** opens `/[locale]/history/[id]` (detail view showing full widgets re-rendered from JSONB).
- **Delete action:** confirms via dialog, fires `DELETE /api/analyses/:id`, optimistic remove + revert on error.
- **Pagination:** "Load more" button calls `GET /api/analyses?cursor=...`. Cursor stored client-side.
- **States:** loading skeleton (8 cards), empty ("No saved analyses yet. Analyze a video to see it here."), error ("Could not load your history. Try again.").

### 3.6 Dashboard "Recent analyses" widget

Component `<RecentAnalyses />` on `app/[locale]/dashboard/page.tsx`:

- Server component, fetches `GET /api/analyses?limit=5` server-side.
- Renders 5 mini-cards (thumbnail, title, processed_at, dominant sentiment chip).
- "View all →" link to `/[locale]/history`.
- Empty state mirrors `/history` empty state.

### 3.7 Privacy + Terms text updates

Add to `app/[locale]/privacy/page.tsx`:

> We store the aggregated analysis results (sentiment percentages, top words, emoji frequencies) for 30 days, associated with your account. Raw comment text is processed in memory and never written to disk. After 30 days, results are automatically purged. You can delete any saved analysis at any time from your history page.

Add to `app/[locale]/terms/page.tsx`:

> Analysis results saved to your account are retained for 30 days from the date of analysis. You may delete any analysis at any time. If you delete your account, all associated analyses are removed immediately.

EN-only in this sprint. RU-locale shows the disclaimer block (per §4.7 below) until lawyer review.

## 4. Track B2 — i18n infrastructure

### 4.1 Library

`next-intl` (de-facto standard for Next.js 16 App Router; Next.js native i18n is deprecated for App Router).

### 4.2 Locales

- `en` (English) — fallback.
- `ru` (Russian).

Other languages out of scope (sentiment lexicon roadmap is separate from UI locale roadmap).

### 4.3 URL routing strategy

**Research-driven decision in PLAN phase.** Compare:

1. Sub-path: `/en/...` + `/ru/...` (Next.js i18n native, hreflang, SEO-optimal)
2. Sub-domain: `en.tubemine.tech` + `ru.tubemine.tech` (DNS complexity, SEO good)
3. Query param: `?lang=ru` (simplest, weak SEO, fragile cache keys)
4. Cookie-only / single URL (worst SEO, duplicate content penalty)

PLAN phase must research how Linear, Vercel, Stripe, Polar, GitHub, Twilio handle i18n in 2025-2026 and cite sources. Initial leaning: sub-path with hreflang. PLAN must confirm or override.

Routing artifact (regardless of choice): all routes resolve to a single canonical locale per request. No mixed-locale page renders.

### 4.4 Default locale + persistence

- **First visit:** parse `Accept-Language` header. If first language tag matches `ru-*` → serve RU locale. Otherwise → serve EN locale.
- **Manual switch:** UI dropdown sets `NEXT_LOCALE` cookie (1 year expiry). Subsequent visits prefer cookie over `Accept-Language`.
- **Anonymous + signed-in:** same flow. Locale is a UI-layer decision, not tied to auth.
- **Crawlers:** serve locale based on URL path (no header sniffing). Allows Googlebot to index both locales.

### 4.5 Translation source

- Translations authored via `pal__chat` with `deepseek/deepseek-v4-flash` (cheap, locale-aware). Founder reviews `messages/ru.json` diff before merge.
- One JSON file per locale: `messages/en.json`, `messages/ru.json`. Namespaced by page/component (e.g. `landing.hero.title`, `dashboard.quota.label`).
- Strict key parity enforced by CI: both files must have identical key sets. PLAN includes a lint step.

### 4.6 Language switcher UI

- **Desktop:** placed in header, right of nav links, before `Sign in / Get started` buttons. Format: text dropdown showing current locale (`EN ▾`) with menu items `EN — English` and `RU — Русский`.
- **Mobile:** inside hamburger menu, top item.
- **Behavior:** clicking an option sets `NEXT_LOCALE` cookie, then navigates to the same logical route in the new locale (e.g. `/en/pricing` → `/ru/pricing`).
- **Component:** `<LocaleSwitcher />` in `src/components/locale-switcher.tsx`. Uses `next-intl` `useLocale` + `useRouter`.

### 4.7 What gets translated

**Bilingual** (`messages/en.json` + `messages/ru.json`):

- Landing (hero, all feature sections, FAQ, pricing teaser, footer CTAs)
- Dashboard (sidebar, quota card, recent analyses widget, empty states, errors)
- Pricing page (copy, pricing FAQ, manage subscription button)
- Profile page (Account / Plan / Billing / Danger zone labels and descriptions)
- /history page (filters, empty state, action menus, dialogs)
- /docs page
- /changelog page (release notes; entry bodies bilingual)
- Login page (Google OAuth CTA, legal blurb)
- Error pages (404, 500, generic)
- Toast messages (success, error, info)
- Form validation errors
- Email subjects + bodies (welcome email)

**EN-only with RU-locale disclaimer:**

- Privacy page
- Terms page

Disclaimer block (rendered above content when `locale === 'ru'`):

> Эта страница пока доступна только на английском. Русская версия появится после юридической проверки.

### 4.8 Typography for Cyrillic

- SF Pro Display (primary) and Inter (fallback) both support Cyrillic. DESIGN.md font stack unchanged.
- Verify hero H1 + section titles render balanced in RU (Cyrillic words tend to be longer than EN equivalents). If overflow occurs at 375px on key headlines, adjust per-locale `letter-spacing` or `font-size` via i18n-aware CSS class.

### 4.9 SEO

- `<html lang="en">` or `<html lang="ru">` per route.
- `<link rel="alternate" hreflang="en" href="https://tubemine.tech/en/..." />` and `hreflang="ru"` counterpart in every page `<head>`.
- `og:locale` meta tag.
- `sitemap.xml` includes both locales for every public route.
- Canonical URL points to the locale-specific path.

### 4.10 Analyses + i18n interaction

- Analyses are locale-agnostic at the data layer. `video_title` stored as-is from YouTube (could be any language).
- UI labels (button text, empty state copy, sentiment chip text) render in the user's current UI locale.
- Switching locale mid-session does not re-fetch analyses. Card grid re-renders with new UI labels.

## 5. Architectural decisions

| Decision | Choice | Why |
|---|---|---|
| Auto-save trigger | Best-effort inline at end of `POST /api/extract` | Simplest path; no background queue needed at current traffic |
| Same-video re-analysis | UPSERT on `(user_id, video_id)`, refresh `expires_at` | Cleaner UX (one history entry per video), avoids clutter |
| Delete semantics | Hard delete | GDPR right-to-erasure friendly; no business value to soft-delete in Phase 0 |
| Pagination | Cursor-based (processed_at desc, id desc as tiebreaker) | Stable under inserts; no offset-skew issues |
| Cron auth | `Authorization: Bearer ${CRON_SECRET}` header | Vercel Cron pattern; same as Polar webhook secret recovery pattern |
| Cron schedule | Daily 03:00 UTC | Off-peak, gives buffer before active hours |
| RLS reads | Yes (via Supabase Auth user) | Existing pattern; service role for writes only |
| Translation library | `next-intl` | Standard for Next.js 16 App Router; native i18n deprecated |
| Cookie name | `NEXT_LOCALE` | `next-intl` convention |
| Cookie expiry | 1 year | Standard for locale persistence |
| Translation tooling | `pal__chat` with `deepseek/deepseek-v4-flash` + founder review | Cheap; founder is bilingual native speaker |
| Search on /history | Client-side initially | 30 days × ~20 analyses/user = small data set; server-side later if needed |
| Track ordering | B1 (persistence) first, B2 (i18n) second | i18n wraps existing pages; needs pages built first to wrap |

## 6. Constraints (no exceptions)

- **Stack unchanged:** Next.js 16.2.6, Tailwind v4, shadcn base-nova, Supabase Auth, Polar billing, Zod 4.
- **Existing API contracts preserved:** `/api/extract` response shape must not change (only side effect added). Polar webhook handlers in `src/lib/subscription.ts` untouched.
- **Service role pattern for writes:** all DB inserts/updates go through `createServiceClient()` (`src/lib/supabase/server.ts`). RLS-protected reads use user-scoped client.
- **Vercel Analytics events:** `paste_attempted`, `preview_loaded`, `extract_completed`, `extract_failed`, `csv_downloaded` keep existing names. New events allowed (e.g. `analysis_saved`, `analysis_deleted`, `locale_switched`).
- **No em-dash:** all user-facing text (UI, emails, FAQ, legal) follows `~/vault/feedback/no-em-dash.md`. Use `,` `.` `()` `:` `-` instead.
- **Mobile-first:** WCAG 2.2 AA, 375px viewport zero overflows, ≥44×44px tap targets.
- **Polar webhook UUID validation:** preserved in `src/lib/subscription.ts` (already shipped, do not regress).
- **Existing quota system:** anonymous 1k/month per IP, Free auth 5k/month, Pro 100k/month. PRD §1.6 numbers, not the previous /vault feedback that said 100.

## 9. Acceptance tests

**Track B1:**

1. **Save on extract:** Sign in as test user. Extract video A. Verify `SELECT * FROM analyses WHERE user_id = ? AND video_id = ?` returns one row with non-null `sentiment`.
2. **Anonymous no-save:** Extract video B anonymously. Verify no row inserted.
3. **UPSERT semantics:** Re-extract video A (same user). Verify same row updated, `processed_at` refreshed, `expires_at` extended.
4. **List paginated:** Insert 25 fixture rows. Call `GET /api/analyses?limit=10`. Verify 10 returned, `nextCursor` non-null. Call with that cursor. Verify next 10. Third page: 5 + null cursor.
5. **Single fetch:** `GET /api/analyses/:id` returns 200 with payload. With wrong owner: 404 (RLS).
6. **Delete:** `DELETE /api/analyses/:id` returns 200. Subsequent `GET` returns 404.
7. **Cron purge:** Insert row with `expires_at = now() - interval '1 day'`. Call cron endpoint with `Authorization: Bearer $CRON_SECRET`. Verify `{ purged: 1 }`. Row gone.
8. **Cron auth:** Call cron endpoint without `Authorization` header. Verify 401.
9. **/history UI:** Sign in, navigate to `/history`. Verify auth gate passes, cards render, search filters in real time, delete confirms via dialog.
10. **Dashboard widget:** Sign in, visit `/dashboard`. Verify "Recent analyses" widget shows 5 latest or empty state.

**Track B2:**

1. **First visit RU:** request `/` with `Accept-Language: ru-RU,ru;q=0.9`. Verify redirect to RU locale URL, content in Russian.
2. **First visit EN:** request `/` with `Accept-Language: en-US,en;q=0.9`. Verify EN content served.
3. **Manual switch persists:** open `/en/`, click locale switcher → RU. Verify URL changes to RU path, content swaps, cookie set. Reload. Verify still RU.
4. **Locale-aware redirect:** logged out user hits `/ru/history`. Verify redirect to `/ru/login?next=/ru/history`.
5. **Privacy disclaimer:** open `/ru/privacy`. Verify disclaimer block visible above EN content.
6. **hreflang:** inspect `<head>` of `/en/pricing`. Verify both `hreflang="en"` and `hreflang="ru"` link tags present, both pointing at correct localized URL.
7. **Key parity lint:** add a key to `messages/en.json` only. Run lint. Verify fails. Restore parity. Verify passes.
8. **Sitemap:** request `/sitemap.xml`. Verify includes `/en/...` and `/ru/...` entries.
